# The prompt carries a bounded tail, and the state stops being the only record

While engaged the projection sent the head — the operating rules, the procedure spec, the state core and the scratch state — plus the newest tool pair and the current user turn, and nothing else. Two classes of material therefore had no route into the prompt: a user turn the execution state did not anticipate, and a fact whose relevance was not recognized when it was first observed. The measured cost was concrete. A mid-run skill invocation was dropped outright — `message_end` returns early while a procedure is engaged (`src/index.ts:271`) and the projection drops every custom and developer message (`src/projection.ts:54-56`) — so the model never saw it, and a second procedure skill could still swap the head's rules slot through `lastCustom`. The abandoned `beta` branch answered that with a succession protocol: a mid-run procedure-skill invocation starts a successor with declared carry (its ADR 0007), and a schema-less invocation ends the procedure (its ADR 0009). That is protocol where visibility would do, and it turns every extra skill invocation into a lifecycle event.

We change the projection instead. Behind the state core rides the **tail**: the most recent stored messages, returned byte-unchanged, under a byte budget. Recency and anything the execution state did not record are simply visible, and the state stops being the sole sufficient statistic. A `state_recall` tool reads back what the tail has evicted, from the session's own transcript. The observation window collapses into the tail — its newest messages *are* the step's observation — so the window walk, its pair-pairing rule and the degraded-window path are deleted, and a degraded step narrows to "the head is intact and the tail is empty". A second user turn, a skill invocation included, gets no special handling: it is in the tail, the model can answer it, and the state is untouched. This supersedes the `beta` branch's succession line, whose numbers (0007–0009) stay spent.

## Considered options

- **State-only, generalized** (the paper's shape): engage everywhere, keep the triple, author a schema per domain. Cheapest, keeps the prompt `O(1)`, and keeps exactly the blindness above. No amount of schema authoring answers late-recognized relevance, because an author cannot declare a key for a fact nobody recognized.
- **The succession protocol** (`beta`, its ADR 0007 and 0009): a successor procedure with declared `x-state.carry`, plus a notice for a schema-less ride. Covers the hole with a lifecycle event per extra skill invocation and leaves the underlying blindness — the projection still hides the conversation the new invocation is about — in place. Rejected.
- **Summaries over the transcript** (the shape of magic-context, pi-blackhole and billion-context; `C:\Users\vadash\Documents\research\skill-state-vs-pi-context-plugins.md`): keep the growing transcript and replace old ranges with prose. Rejected: the paper's budget-matched controls put prose compression far below structured state at equal budget, and a summarizer is a second model call per compaction where this runtime makes none.
- **The tail without recall**: rejected — it makes eviction the hard boundary of what the model can know, which is the paper's third stated limitation — audit and provenance tasks — promoted to a permanent blind spot.

## Consequences

- The prompt is bounded, not `O(1)`. Section 2's complexity claim changes with it: the budget bounds the prompt, the number of steps bounds only the transcript. The paper's headline invariant is given up deliberately.
- The tail keeps assistant prose, so reasoning re-enters the prompt for as long as it stays in the tail. The execution state remains the durable carrier; the tail is transient by construction, and nothing may be read from it after it evicts except through recall.
- Only the known live-state injections — `goal-mode-context`, `plan-mode-context`, the todo nudges, TTSR injections, todo reminders — are dropped from the tail. Every other stored message is kept, the skill-prompt customs included, which is what makes a mid-run invocation visible.
- `CONTEXT.md` retires **Observation window** and redefines **Observation**, **Degraded step**, **Cache ceiling** and **Nudge**; **Tail**, **Prompt budget**, **Eviction**, **Recall** and **Durable mirror** join the glossary.
- Acceptance widens to four classes, and the last two are what this ADR exists to make possible: an ordinary coding session, a long research run, trajectory-as-objective work (an audit, "what changed and why", debug provenance), and a multi-skill session. Each is verified by a real session the user records and the transcript is read afterwards; no synthetic session harness is built for them.
